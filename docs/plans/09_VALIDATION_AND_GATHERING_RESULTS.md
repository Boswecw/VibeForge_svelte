# 09 — Validation and Gathering Results

## Validation rule

```text
A feature is not complete until it has a receipt, a negative fixture, and a visible failure state.
```

## MVP acceptance gates

| Gate | Pass condition |
|---|---|
| Local-first value | Full MVP workflow runs without cloud |
| Active tree protection | Agent cannot mutate active tree by default |
| Vault durability | Backup/restore preserves receipt hashes |
| Context control | Cloud payload preview exists before cloud job |
| Privacy | Forbidden analytics fields are blocked |
| Command safety | Risky commands are blocked or approval-gated |
| Board review | Cards include evidence, confidence, risks, and options |
| Developer authority | approval/modify/reject/defer/send-back produce receipts |
| Kill switch | Running workcell stops and records cancellation |
| No fabricated state | UI degraded states derive from real process/vault state |
| Rollback proof | Patch receipt identifies source commit and patch manifest |

## Golden fixture set

| Fixture | Expected result |
|---|---|
| `.env` included in context candidate | excluded + redaction receipt |
| symlink points outside repo | blocked + security event |
| `rm -rf` generated by agent | blocked |
| analytics event includes `src/auth/session.ts` | blocked |
| cloud job requested without preview | blocked |
| patch manifest hash mismatch | receipt validation fails |
| board reviewers disagree on auth change | material disagreement shown |
| validation command fails | patch cannot promote without risk acceptance |
| worktree path outside managed root | blocked |
| user kill switch during run | cancelled state + receipt |

|---|---:|
| Successful local MVP workflows | ≥ 80% of beta users |
| Active tree mutation incidents | 0 |

| Budget cap enforcement | 100% |

## Post-production gathering

Collect only privacy-safe operational metrics:

```text
feature usage
route class
success/failure
duration
credit cost
error category
quota events
billing events
app version
OS family
```

Never collect source content, prompts, outputs, paths, repo names, branch names, commit messages, test logs, or secrets as analytics.

## Beta graduation criteria

VibeForge can graduate from private beta when:

- Local workflow is stable on at least three repo families.
- Privacy gates have zero known bypasses.
- Cockpit makes risk and evidence understandable.
- Patch receipts survive backup/restore.
- Cloud mode is optional and approval-gated.
- Users choose VibeForge for trust/governance, not just code generation.
